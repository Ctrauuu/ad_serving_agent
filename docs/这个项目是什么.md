01-这个项目是什么
01-这个项目是什么
本篇讲清楚广告投放执行 Agent 到底是个什么产品、给谁用、核心对象是什么、能做什么不能做什么。后续模块文档和开发链路都建立在这些定义之上。

1. 产品定义
广告投放执行 Agent 是一个面向企业市场投放团队的 AI 投放执行系统。它让 AI 真正参与广告投放的策略制定、投放过程监控、数据异动识别、干预动作建议与执行，把过去"人工凭经验配置 + 人工盯盘 + 事后看报表"的工作方式，变成一条可追踪、可审计、可回滚的投放执行闭环。

它不是只算 ROI 的数据看板，也不是只生成策略建议的辅助工具，而是一个能推进投放流程、能主动发现问题、能给出可执行动作、并在高风险节点让人拍板的执行型 Agent。AI 负责发现问题和给建议，人负责审批高风险动作，所有动作留痕可回滚——这是它区别于普通投放工具的核心。

2. 服务对象
角色	在系统里的核心诉求
市场投放人员	高效创建投放活动，少做手工配置，拿到可解释的策略建议
增长运营人员	及时发现投放异动，拿到原因和可执行建议，不用全天盯盘
投放负责人	管控预算和风险，审批关键动作，看复盘做决策
销售团队	把线索质量和成交结果反馈回流到投放评估（本项目用 mock 数据模拟）
3. 核心业务对象
系统的核心业务对象是**一场广告投放活动（Campaign）**的完整生命周期。围绕这个对象，系统管理投放目标、投放策略、广告计划与广告组、人群与素材、实时投放指标、预算消耗、数据异动、异常原因、干预建议、审批记录、执行动作、复盘报告、历史案例等一整套数据。

一条活动从"草稿"出发，依次经过"目标已结构化 → 策略已确认 → 任务创建中 → 投放中 →（可能暂停/恢复）→ 已结束"的状态流转，每个状态对应一组可执行的业务动作和可观测的数据。

4. 核心能力
系统围绕投放生命周期提供十项核心能力：

投放目标结构化：把投放人员用自然语言描述的目标，自动解析成推广对象、目标人群、预算、周期、转化目标、渠道范围、风险限制等结构化字段。

投放策略生成与依据召回：结合历史活动、渠道规则、产品卖点和预算约束，生成渠道组合、预算拆分、广告组结构、人群定向、素材测试方案和预期指标，并附每条建议的依据。

广告任务编排与平台工具调用：把策略拆成广告计划、广告组、人群、素材、关键词、出价、预算，通过统一工具协议调用广告平台创建任务并同步状态。

实时监控与指标聚合：持续拉取曝光、点击、消耗、线索、有效线索、成交、ROI，按活动、渠道、广告组、素材、人群和时间窗口聚合。

数据异动识别：结合固定阈值、动态基线、同比环比、投放阶段和预算消耗节奏，识别消耗异常、转化骤降、成本飙升、素材疲劳等问题，避免把正常波动误判为风险。

异动原因归因：综合素材、人群、渠道、落地页、销售反馈和历史相似案例，生成多个带证据来源的原因假设。

投放干预建议生成：按异常类型生成暂停、调预算、调出价、换素材、收窄人群等建议，每条带指标证据、触发规则、预估影响和风险说明。

Human-in-the-loop 风险审批：按风险分级决定动作走向——低风险可自动执行或一键确认，高风险（暂停、调预算、调出价、切换渠道）必须投放负责人审批。

动作执行与回滚：确认后调用广告平台执行动作，记录动作前后状态、执行人、工具调用结果、失败原因，必要时支持回滚。

投放复盘与经验沉淀：活动结束后生成复盘报告，对比干预前后效果，把有效策略与失败案例沉淀进知识库，供后续策略生成和归因召回。

5. 产品边界
为了让项目可落地，以下范围本期明确不做：

不对接真实广告平台：巨量引擎、腾讯广告、百度推广等真实平台需要账户权限和真实预算，本期用模拟广告平台（以 MCP Server 形式封装）代替，接口语义对齐真实平台。

不实现完整 CRM 和成交归因：销售团队反馈和成交数据用 mock 数据注入，不实现完整的客户跟进和成交归因系统。

不引入实时流式计算引擎：实时监控用定时拉取加缓存聚合的方式模拟近实时，不引入流式引擎。

不做多租户和复杂组织架构：权限用简单角色控制（投放人员、运营、负责人），不做多公司多部门隔离。

不实现真实支付结算和素材 AIGC 生成：预算是数字字段，素材用 mock 管理。
