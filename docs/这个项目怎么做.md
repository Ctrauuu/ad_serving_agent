03-这个项目怎么用
本篇讲清楚谁在什么入口下、按什么步骤使用这套系统，以及每类角色各自的操作路径。后续的模块拆分、页面设计和开发链路都从这些使用步骤里抽象出来。

1. 使用角色
角色	目标	在系统里做什么
市场投放人员	高效创建投放、少做手工配置	新建活动、配置目标、确认结构化目标、触发策略生成、发起广告任务创建
增长运营人员	及时发现异动、拿到可执行建议	查看监控看板、查看异常、触发归因、跟踪建议与执行效果
投放负责人	管预算控风险、审批关键动作	审批策略、审批高风险干预建议、查看复盘报告
销售团队	反馈线索质量影响投放评估	本期用 mock 数据注入线索质量与成交反馈，不直接操作界面
2. 真实使用入口
企业内部 Web 投放管理系统。投放人员、运营、负责人日常都在这个 Web 系统里完成投放工作。

3. 开发展示入口
Web 页面（Vue 3 + Element Plus）。前后端联调、演示、交付都通过 Web 完成。真实入口即 Web，无差异。

4. 主流程
一场活动从创建到复盘的完整链路如下：

flowchart TD
  A["投放人员新建活动并描述目标"] --> B["系统结构化投放目标"]
  B --> C["投放人员确认结构化目标"]
  C --> D["系统生成投放策略与依据"]
  D --> E{投放负责人确认策略}
  E -->|驳回| D
  E -->|确认| F["系统拆广告任务并调用广告平台创建"]
  F --> G["活动进入投放中,系统实时监控"]
  G --> H{是否出现异动}
  H -->|否| G
  H -->|是| I["系统归因分析生成原因假设"]
  I --> J["系统生成干预建议"]
  J --> K{风险分级}
  K -->|低风险| M["系统执行动作"]
  K -->|高风险| L{投放负责人审批}
  L -->|驳回| G
  L -->|通过| M
  M --> N["记录执行结果与回滚状态"]
  N --> G
  G --> O{活动结束}
  O -->|否| G
  O -->|是| P["系统生成复盘报告并沉淀案例"]

5. 关键场景
场景一：新活动不知道怎么投
投放人员接到一个新产品推广任务，预算 8 万，目标是获取高质量销售线索，优先控制成交成本。他在系统里新建活动，用自然语言描述目标，系统把目标结构化成渠道范围、预算、周期、转化目标等字段。他确认后触发策略生成，系统召回历史相似活动，生成渠道组合、预算拆分和素材测试方案，并附依据。负责人查看依据后确认，活动进入任务创建。

场景二：广告组消耗过快但线索质量差
活动上线后，某个广告组半小时消耗了全天预算的 40%，但有效线索率只有 10%。系统在监控中发现这个广告组消耗速度异常且有效线索率连续下降，生成异常记录。运营触发归因，系统结合素材、人群、渠道流量和销售反馈，判断可能是素材吸引了低意向人群，给出"暂停该广告组并把预算转向 ROI 稳定渠道"的建议。因为涉及暂停和调预算，建议进入负责人审批。负责人查看证据后通过，系统执行暂停和预算转移，并记录动作前后状态。

场景三：活动结束复盘
活动结束后，负责人触发复盘。系统汇总整体指标、各渠道效果、所有异常和干预动作，对比每个动作前后的消耗、成本、线索质量变化，生成复盘报告。系统把"暂停低质量广告组使整体 CPA 下降 18%"这样的有效策略沉淀进案例库，把"误暂停导致线索断流 2 小时"这样的失败教训也沉淀进去。下次类似活动生成策略时，系统能召回这些经验。
