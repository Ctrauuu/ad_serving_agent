02-为什么要做这个项目
本篇只回答一个问题：广告投放这件事，为什么需要做成一个系统，而不是继续靠人盯盘。讲的是业务 Why，不是技术方案。

1. 项目由来
效果广告投放是企业获客的核心手段，但投放工作长期停留在"人盯盘 + 经验决策"的模式。一个投放人员每天要同时管几个到十几个广告平台账户，手动配置广告计划、调整出价、盯消耗和线索数据，遇到异常再凭经验判断要不要暂停或加预算。

这种模式在过去能跑，是因为投放规模小、渠道少。但随着投放渠道越开越多、数据维度越来越细、预算节奏越来越快，靠人盯盘已经盯不过来。尤其夜间和周末没人盯，等周一发现问题时预算已经浪费了。企业需要的不再是"一个能看数据的看板"，而是"一个能替人盯、能发现问题、能给可执行动作、还能让人审批把关的执行系统"。

2. 业务痛点
投放团队每天面对六个具体痛点：

策略依赖个人经验，且不可解释。新活动投哪些渠道、预算怎么拆、人群怎么选，主要靠投放人员的经验。经验没沉淀成可复用的知识，人员一流动经验就带走；而且即使有经验，也说不清"为什么这么投"，其他人不敢质疑也不敢复用。

渠道规则分散在多个平台。每个广告平台的账户、计划、广告组、素材、人群、归因口径都不一样，投放人员要在多套规则间切换，容易出错，也很难统一对比。

预算调整滞后于数据变化。数据异常往往要等投放人员手动看到报表才发现，等发现时预算已经浪费在低质量流量上。调整动作总是慢半拍。

异常发现不及时。消耗突增、转化骤降、有效线索率下滑这些情况，靠人工盯盘很难分钟级发现。晚上和周末更是盲区。

人工盯盘成本高。投放人员每天大量时间花在看数据上，而不是做更高价值的策略优化。人力被锁死在低效的盯盘动作里。

投放动作缺少复盘依据。为什么暂停了某个广告组、为什么加了预算、加完之后效果怎么样，这些动作和结果常常没对上。复盘时只能凭印象，下次活动还是凭感觉。

3. 现有流程与信息处理瓶颈
把这些痛点放到现有工作流程里看，瓶颈更清楚：

活动筹备阶段：投放人员接到新活动任务，要回忆"上次类似活动怎么投的"，但历史活动数据散落在多个平台和 Excel 里，很难快速调出来对比。策略质量取决于个人记忆和经验。

投放执行阶段：活动上线后，投放人员需要频繁登录各平台看数据。数据是看到了，但"看到"和"看懂"是两回事——消耗上升是好是坏、点击下降要不要暂停，需要结合投放阶段、线索质量、历史趋势综合判断，人脑很难实时做多维判断。

异常处理阶段：发现异常后，投放人员要判断原因（是素材问题、人群问题、还是渠道流量问题），再决定动作（暂停、调预算、换素材）。判断和动作之间经常脱节，动作做完了也不知道有没有改善。

复盘阶段：活动结束后要写复盘，但中途的动作和效果没有系统记录，复盘报告只能写个大概。有效经验没沉淀，失败教训没总结，下次活动从零开始。

整条流程的瓶颈在于：人脑做不了实时多维监控和归因，人手做不了分钟级响应，人脑记不住所有动作和效果的对应关系。这些恰好是系统擅长的事。

4. 为什么需要系统化解决
有人会问：给投放人员配一个更好的数据看板不行吗？为什么一定要做成一个执行型 Agent？

原因是看板只能解决"看到数据"的问题，解决不了"判断、决策、执行、沉淀"的问题：

看板告诉你 CPA 升高了，但不告诉你为什么升高、该怎么办。

看板需要人主动去看，晚上和周末没人看就失效。

看板不执行任何动作，暂停和调预算还是要人手动操作。

看板不沉淀经验，下次活动还是从零开始。

只有把"监控 → 识别 → 归因 → 建议 → 审批 → 执行 → 复盘 → 沉淀"做成一个闭环系统，才能真正解决这六个痛点。而且这个系统不能完全自动化——涉及真实预算的动作必须有人的审批把关，否则 AI 判断失误会造成直接损失。所以它必须是一个"AI 执行 + 人审批"的 Agent，而不是一个全自动机器。

5. 解决后的价值
系统上线后，投放团队的工作方式会发生几个可见变化：

策略从"凭经验"变成"有依据"。新活动策略由系统生成，并附历史相似活动、渠道规则、预算拆分逻辑等依据，投放人员能看懂为什么这么投，负责人敢批。

异动从"事后发现"变成"分钟级识别"。系统持续监控，异动在分钟级被发现，并自动给出原因假设和干预建议，不用人全天盯盘。晚上周末也不留盲区。

动作从"手动操作"变成"可审批可回滚"。暂停、调预算等高风险动作必须负责人审批才能执行，动作前后状态完整记录，做错了能回滚。每个动作可审计。

经验从"随人流失"变成"越积越准"。活动复盘自动生成，有效策略和失败案例沉淀进知识库，下次活动生成策略时能召回复用。系统用得越久越准。

一句话概括价值：把广告投放从"人工凭经验配置、人工盯数据、事后看报表"，变成"AI 生成策略、实时监控、识别异动、生成可审批的干预动作，并把执行结果沉淀为后续策略经验"。
